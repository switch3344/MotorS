# Видео hero — кинорежим и финал с дугой v5

Источник пользователя: https://www.youtube.com/watch?v=3LI1MHnLwB0 — Авторевю / Nissan GT-R. Источник указан под превью и в финальном кадре. Голоса и музыки нет.

## Монтаж

`public/video/gtr_final_ready_v5.mp4`: 1920×1080, 30 FPS, H.264 yuv420p, AAC stereo 48 kHz, около 21.2 с, 12.26 MB. CRF 18, fastdecode, faststart, ключевой кадр раз в секунду, без B-кадров, один reference frame.

Прерывистый приём сохранён: хронологический разгон, чёрные вставки «А» / «ВЫ ХОТИТЕ» / «ТАК ЕЗДИТЬ?» после старта около 2, 50 и 150 км/ч, затем до примерно 230. Повторных рывков и возвратов к началу нет. Во вставках тишина, микро-фейды 3 ms убирают щелчки звуковых склеек.

В финале источник плавно уходит в полностью чёрный фон. За 1.6 с слева направо проводится тонкая дуга с коротким красным кончиком; затем остаётся белая линия. Текст Manrope: «MotorServiceKRD», «Чтобы ехать уверенно», «Диагностика двигателя». Дуга и текст отрисованы в 1080p без фона из видео, шумовых оверлеев и свечения. Звук через crossfade снижается до 28%, затем мягко затухает.

Исходник 720p масштабируется Lanczos и проходит Contrast Adaptive Sharpen (`cas=strength=0.28:planes=1`), только по яркостной компоненте. Это повышение локальной чёткости, а не восстановление отсутствующих деталей. То же применяется к `gtr-preview-v5.mp4` (беззвучные 8 с) и `gtr-poster-v2.jpg`.

## Плеер

Видео открывается в нативном модальном dialog на весь viewport через React portal. Шапка, края hero и элементы страницы не перекрывают фильм. Во время просмотра заблокирована прокрутка страницы; после выхода восстанавливаются overflow, scrollbar gutter, положение страницы и фокус кнопки.

Два video-элемента постоянно смонтированы: превью на странице и полный ролик внутри закрытого dialog. При открытии не меняется src и не пересоздаётся video. Тихая подготовка полного файла начинается после загрузки прелоадера двигателя. При модальном просмотре фоновая 3D-сцена приостанавливается.

Нет нижнего таймлайна, цифрового счётчика и полосы управления. Нажатие на кадр, Enter и Space ставят паузу и продолжают просмотр. Небольшие иконки звука, полного экрана и выхода скрываются через 2 с без движения указателя; на телефоне остаются доступными. Escape закрывает dialog. Звук включается только по явному нажатию просмотра, на уровне 70%. При уходе вкладки в фон воспроизведение ставится на паузу.

Кнопка просмотра на странице сохранена по референсу Antigravity: тёмная вытянутая форма, Play слева, текст в одну строку. На широком экране она плавно следует за указателем; на узком экране, touch и reduced-motion остаётся статичной. Reduced-motion не запускает превью автоматически.

## Повторная сборка

Python + Pillow с FreeType/WOFF2; FFmpeg с drawtext и CAS. Используются проектные Manrope WOFF2 и системный Impact для перебивок; шрифты Windows не распространяются.

```powershell
python scripts/render-user-montage.py --ffmpeg C:/path/to/ffmpeg.exe --input path/to/source.mp4
```

Команда сначала запускает `scripts/render-hero-outro.py`, создающий PNG-кадры дуги в игнорируемой `.qa/outro-v5`. Старые опубликованные медиа оставлены для уже открытых вкладок с предыдущей версией.

## Проверка

TypeScript check и production-сборка с VITE_BASE_PATH=/MotorS/ прошли. Полный MP4 декодируется FFmpeg без ошибок. Проверен нативный dialog: в accessibility tree остаются только фильм и его управление, шапки нет. Локальный прогон на 1440×900: 4 пропущенных кадра из 551, 0 buffer stalls; это конкретный замер, не гарантия для всех устройств. Дальнейшая проверка включает восстановление страницы, мобильную версию и публичную публикацию.

Финальная проверка кинорежима: dialog занимает ровно 1440×900 и 390×844 без полосы прокрутки. Нажатие на кадр даёт paused, повтор запускается с конца. На телефоне крестик закрывает modal; Esc на desktop снимает open, восстанавливает inline overflow/gutter и фокус «Просмотреть видео со звуком». Нижних range-input и панелей нет.
